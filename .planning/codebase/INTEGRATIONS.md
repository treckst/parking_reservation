# External Integrations

**Analysis Date:** 2026-11-09

## APIs & External Services

**Text embeddings:**
- OpenAI embeddings convert whole PDF pages into vectors in `ingested_mock_data/seed_vector_ingest.py`.
  - SDK/Client: `langchain_openai.OpenAIEmbeddings`, declared through `langchain-openai>=1.7.4` in `pyproject.toml`.
  - Auth: `OPENAI_API_KEY`, read after `load_dotenv(root / ".env")` in `ingested_mock_data/seed_vector_ingest.py`.
  - Model: no explicit model argument; the package default is used and printed at completion. `ingested_mock_data/README.md` names the expected default, but code does not enforce a model name.
  - Input: `PyPDFLoader(mode="page")` produces one document per page; automatic embedding input splitting is disabled via `check_embedding_ctx_length=False` in `ingested_mock_data/seed_vector_ingest.py`.
  - Execution: `Chroma.add_documents` invokes embeddings; repeat runs still call the API. No application-specific rate-limit, retry, or batching policy is configured in `ingested_mock_data/seed_vector_ingest.py`.

**Vector database HTTP service:**
- A local Chroma service accepts vectors, document text and metadata through `chromadb.HttpClient(host="127.0.0.1", port=8000, ssl=False)` in `ingested_mock_data/seed_vector_ingest.py`.
  - SDK/Client: `chromadb==1.5.9` and `langchain-chroma>=1.0` in `pyproject.toml`.
  - Auth: no client credentials or server authentication are configured in `ingested_mock_data/seed_vector_ingest.py` or `docker/compose.yaml`.
  - Availability check: `client.heartbeat()` runs before embeddings and insertion in `ingested_mock_data/seed_vector_ingest.py`.

**Declared but not implemented services:**
- `langsmith` is declared in `pyproject.toml`, but explicit application tracing configuration is not detected in `ingested_mock_data/seed_vector_ingest.py` or `src/`. Dependency presence alone does not establish an active LangSmith integration.
- Fictional booking, payment, charging, support email and QR-code workflows in `ingested_mock_data/generate_pdfs.py` are corpus content; no corresponding external service integrations are implemented in `src/`.

## Data Storage

**Databases:**
- SQLite fixture at `ingested_mock_data/parking_november_2026.sqlite3`.
  - Connection: script-relative path via `Path(__file__).with_name(...)`; no connection environment variable in `ingested_mock_data/seed_database.py`.
  - Client: standard-library `sqlite3`, with foreign keys enabled and writes inside a connection transaction in `ingested_mock_data/seed_database.py`.
  - Tables: `transport_slots` keyed by `(spot_id, slot_date)` and `reservations` keyed by `reservation_id`, linked through a composite foreign key in `ingested_mock_data/seed_database.py`.
  - Capacity of generated fixture: 1,440 daily slot rows and 720 reservation rows documented in `ingested_mock_data/README.md`; availability is a fixed snapshot, so interval overlap must also be checked by any future consumer.
  - Reruns preserve conflicting existing rows with `ON CONFLICT ... DO NOTHING`; this is not a schema migration or synchronization system (`ingested_mock_data/seed_database.py`).
- Chroma vector collection `parking_documents` in `ingested_mock_data/seed_vector_ingest.py`.
  - Connection: hardcoded local HTTP endpoint; no connection environment variable.
  - Persistence: `chroma_data` Docker named volume at `/data`, configured with `CHROMA_PERSIST_PATH` in `docker/compose.yaml`.
  - IDs: normalized repository-relative source path plus zero-based page number, in the form `source:page:index`, generated in `ingested_mock_data/seed_vector_ingest.py`.
  - Metadata: loader metadata retained; `source` becomes a repository-relative POSIX path. Stable IDs support repeat upserts, while absent source files are not deleted from the collection (`ingested_mock_data/seed_vector_ingest.py`, `ingested_mock_data/README.md`).
  - Verification: the script fetches its inserted IDs and compares counts; it does not perform a semantic retrieval test (`ingested_mock_data/seed_vector_ingest.py`).

**File Storage:**
- Local reference corpus in `ingested_mock_data/pdfs/`: 12 PDFs with three pages each, documented in `ingested_mock_data/README.md` and generated by `ingested_mock_data/generate_pdfs.py`.
- No object-storage SDK or remote file-storage integration is implemented in `ingested_mock_data/` or `src/`.

**Caching:**
- No dedicated application cache is implemented in `src/` or `ingested_mock_data/seed_vector_ingest.py`. Chroma stores vectors persistently; stable IDs do not avoid repeat embedding calls.

## Authentication & Identity

**Auth Provider:**
- No end-user identity provider, session handling or authorization layer is implemented in `src/`.
- Service authentication is limited to the OpenAI API key in `ingested_mock_data/seed_vector_ingest.py`; the script rejects missing keys and its recognized mock-key prefix before service calls.
- Chroma binds the host port to loopback in `docker/compose.yaml`. Keep that local-use assumption explicit when changing deployment; the current client uses HTTP without authentication (`ingested_mock_data/seed_vector_ingest.py`).

## Monitoring & Observability

**Error Tracking:**
- No explicit error tracking service is implemented in `ingested_mock_data/` or `src/`; `langsmith` is a declared dependency only in `pyproject.toml`.

**Logs:**
- Standard output reports database location and row counts in `ingested_mock_data/seed_database.py`.

- `ingested_mock_data/README.md` documents starting and stopping the service; normal Compose shutdown preserves named-volume data.

**CI Pipeline:**
